# Prospective bounded SVG-import receiving

This course exercises a small artwork-import contract, not general SVG/browser compatibility or a new fitting algorithm. No importer, fitter, encoder, decoder or producer import runs until root freezes the sources, fixtures and gates.

## Fixed course and counts

Import the independently authored three-moment Paper Kite sequence once. Check every normalized coordinate against separately supplied expected targets, then consume its saved project through the unchanged offline exporter once. Import the authored square-to-triangle sequence once, preserving both shapes and a nonzero authored fitting residual; do not encode this incompatible sequence.

Refuse an existing output directory without changing its inventory. Refuse five sequences containing unsupported or malformed artwork: a quadratic curve, a transform attribute, multiple visible polygons, a comma immediately after a path command, and non-ASCII numeric digits. These failures must precede fitting.

Fixed-source counts are two successful imports/helper invocations, two calls to existing fitScene, one four-second offline encode, one full 96-frame decode and six pre-fit refusals. Counts follow reviewed source and process receipts, not a dynamic function-call trace. A failed outcome is retained and does not authorize a retry, gate change or parameter sweep.

## Import and fitting gates

Compatible targets must match independent normalized coordinates within 1e-12 stage units, including vertical-axis reversal and common-viewBox centering. Title, duration, moment times and lightShare must follow the sequence. Input sequence/SVG bytes and hashes are retained, sources remain unchanged, and all three authored outlines survive in project.json. The saved project must survive the unchanged parser's roundtrip; preserve the actual outcome rather than infer it from a filename.

At authored moments, independently projecting the compatible fitted scene must match target polygon boundaries within 1e-8 stage units. The incompatible square-to-triangle import must retain both target shapes, report authoredKeyRms > 1e-4, and show independent endpoint boundary mismatch > 1e-4. The independent boundary metric is not asserted equal to the producer's sampled RMS. Nonzero residual is expected behavior, not import failure; no claim is made about unobserved target interpolation or artistic quality.

Existing output must remain byte-identical. Refusal messages and all partial artifacts remain available. This is a concrete unsupported-feature check, not a general fuzzing matrix.

## One ordinary downstream movie

The compatible four-second project yields 96 frames at 1000×714 and nominal 24 fps under the unchanged offline profile. Check producer input/scene/source/movie identities and physical times i/95. The exporter already has per-frame geometric/mask qualification; this importer course does not repeat it.

Fully decode the received movie exactly once, retaining every decoded RGB hash and frame timestamp, with selected PNGs at indices 0, 47, 48, 95 for visual inspection. ffprobe reads stream/container metadata only. Require 96 frames, exact dimensions, VP9, positive time-base tick ≤ 1 ms, strictly increasing finite PTS, and PTS/duration error within one recorded tick. Do not claim exact RGB/browser identity or visual inspection of all frames. No additional render or encode is used to produce the selected-frame sheet.

## Resources and evidence

Use one affinity CPU and one encoder/decoder/filter thread under a 120-second outer course bound, with owned process-group cleanup on timeout. Retain original commands/stdout/stderr/exit records, runtime identities, source hashes before/after, authored inputs, imported outputs, incompatible residuals, movie and receiving measurements. This course adds no historical data, provider calls, private model assets or existing course populations. No performance claim follows from the descriptive execution time.

## Pre-freeze grammar revisions

Before any execution, the same square and triangle were rewritten as equivalent closed straight paths. The square uses relative initial `m`, relative `h/v`, absolute `H/V`, and an explicit return to its first vertex before `z`. The triangle uses initial `M` with an implicit `L` coordinate pair, then relative `l` and `Z`. Expected normalized coordinates remain unchanged. Exactly two additional pre-fit refusals cover `M,100` comma placement and Arabic-Indic numeric digits. The successful import/fit, encode and decode counts are unchanged.
